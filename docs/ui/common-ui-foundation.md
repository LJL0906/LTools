# LTools 公共 UI 基础设计

**日期：** 2026-07-30  
**状态：** 已由用户批准进入开发  
**视觉基准：** `docs/ui/theme-layout-v9.html`

## 目标

先实现链接、笔记、剪切板、设置四个模块共同依赖的主窗口骨架、基础控件和分组管理 UI，为后续独立业务模块提供稳定承载层。本阶段不接入 SQLite，不实现链接 CRUD、笔记编辑器或剪切板业务。

## 设计原则

1. V9 原型是唯一视觉来源，不重新设计。
2. 只抽取已经稳定重复的结构，不建立通用组件大全。
3. 路由是模块激活状态的唯一来源。
4. 分组 UI 共用，链接分组与笔记分组的数据作用域隔离。
5. 页面业务组件通过插槽组合，不让公共布局感知业务数据。

## 组件边界

### 应用层

- `App`：安装路由，提供四个模块入口。
- `AppShell`：组合顶部导航和模块出口。
- `TopNavigation`：渲染品牌、模块导航和当前模块搜索框。
- `ModuleLayout`：提供可配置宽度的左侧栏、拖拽分隔线和右侧内容区。

### 基础控件

- `Button`：仅提供 `primary`、`secondary` 两种稳定变体。
- `IconButton`：统一原型中的小尺寸图标按钮。
- `SearchBox`：统一顶部搜索框视觉，业务搜索逻辑由页面传入。
- `Dialog`：统一弹窗遮罩、标题、正文和底部操作区。
- `ConfirmDialog`：基于 `Dialog` 的确认流程。

### 分组公共 UI

- `GroupSelector`：显示当前分组和可搜索分组列表。
- `GroupMenu`：显示重命名、删除操作。
- `GroupDialog`：新建或重命名分组。
- `DeleteGroupDialog`：删除确认。

分组组件接收 `scope: "links" | "notes"`，但不直接依赖具体 Zustand store。本阶段页面以本地演示数据验证作用域和交互，后续通过 props 接入真实仓储。

## ModuleLayout 左侧栏拖拽（已实现）

- 链接页和笔记页共用 `ModuleLayout` 的拖拽能力，但各自维护独立宽度；切换模块不会共用或覆盖另一模块的宽度。
- 分隔线视觉宽度为 1px，交互命中区约 8px；命中区透明覆盖在分隔线周围，不增加可见留白，也不改变紧凑布局。
- 拖拽统一使用 Pointer Events：`pointerdown` 开始、`pointermove` 更新、`pointerup` 结束，并通过 pointer capture 保证指针移出命中区后仍可连续调整。
- 分隔线及命中区使用 `cursor: col-resize`；拖动期间临时禁用文本选择，结束拖动后恢复。
- 分隔线使用 `role="separator"`、`aria-orientation="vertical"`，并暴露当前值及允许范围。
- 键盘操作：左/右方向键每次调整 8px；按住 Shift 时每次调整 16px；所有结果都必须经过宽度边界约束。
- 链接模块：默认 216px，最小 160px，配置最大值 320px。
- 笔记模块：默认 304px，最小 240px，配置最大值 420px。
- 实际最大宽度同时受容器可用宽度约 40% 限制，即采用“模块配置最大值”和“容器约 40%”中的较小值，避免右侧内容区被过度压缩。
- 第一版通过 `sidebarStateKey` 将各模块宽度保存在前端运行期内存中；切换模块后可恢复各自宽度，刷新页面或重启应用后恢复默认宽度，不接入 `localStorage`、数据库或其他持久化。

## 页面范围

- 链接页：按 V9 展示分组侧栏、标题、链接卡片演示数据，用于验证公共骨架。
- 笔记页：按 V9 展示笔记侧栏和编辑器静态内容，用于验证公共骨架。
- 剪切板页、设置页：只提供与公共壳一致的占位内容，不提前设计独立模块。

## 状态与数据流

- 当前模块：来自 React Router URL。
- 顶部搜索文本：页面局部状态。
- 弹窗开关和当前分组：页面局部状态。
- 分组演示数据：页面局部状态，按 `scope` 分离。
- 当前阶段不创建全局 Zustand store。

## 可访问性

- 导航使用语义化链接和 `aria-current`。
- 图标按钮必须有 `aria-label`。
- 弹窗使用 `role="dialog"`、`aria-modal="true"`，支持 Escape 关闭。
- 搜索框具有可访问名称。

## 非目标

- 不接入 Rust command。
- 不实现 SQLite。
- 不实现 Tiptap 编辑和自动保存。
- 不实现链接真实打开、复制、增删改。
- 不实现剪切板和设置业务。
- 不增加 V9 原型之外的主题、动画或组件。

## 验收标准

1. 四个模块路由可切换，导航高亮正确。
2. 链接页和笔记页的公共顶部结构与 V9 原型一致。
3. 两页分别支持公共分组新建、重命名、删除 UI，数据不互相污染。
4. 960×680 和 720×520 下无关键内容重叠或页面级横向溢出。
5. 单元测试、TypeScript 构建和 Vite 构建通过。
6. 通过实际浏览器截图与两张参考图检查布局、颜色、间距和密度。

## 2026-07-30 用户确认的紧凑密度约束

- 页面和组件的垂直外边距、内边距不超过 24px。
- 页面和组件的水平外边距、内边距不超过 16px。
- 主窗口采用紧凑信息密度，避免无业务意义的大面积空白。
- 链接和笔记模块可以使用不同的文字层级，但必须共用统一字号阶梯与间距阶梯。
- 标题、按钮、搜索框、卡片、列表项和编辑工具栏均使用满足内容与点击需要的最小合理尺寸。
