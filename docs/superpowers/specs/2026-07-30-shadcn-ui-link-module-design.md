# 链接管理模块 shadcn/ui 改造设计

- 日期：2026-07-30
- 状态：待实施
- 范围：UI 基础设施与链接管理模块

## 1. 目标

为 LTools 集成 shadcn/ui，以提升链接管理模块的界面质量与开发效率，并为后续模块提供可复用的 UI 基础。本次改造只调整表现层，不接入 SQLite，不改变链接、分组、搜索等现有业务规则。

## 2. 技术方案

采用 shadcn/ui、Tailwind CSS 4、Radix 组件基础和项目已有的 Lucide React。

保留现有 CSS Token，将颜色、圆角、间距等映射到 shadcn/ui 主题变量。业务布局仍由项目维护，基础交互控件优先使用 shadcn/ui。

## 3. 实施范围

### 3.1 UI 基础设施

- 初始化 shadcn/ui 与 Tailwind CSS 4。
- 配置 Vite 和 TypeScript 路径别名。
- 新增 shadcn/ui 配置与类名合并工具。
- 按需引入 Button、Card、Dialog、Alert Dialog、Input、Textarea、Select、Dropdown Menu、Tooltip、Badge、Empty 和 Toast 等组件。
- 维持当前紧凑型桌面 UI 的颜色、字号和间距约束。

### 3.2 链接管理模块

改造以下界面：

- 分组侧栏及分组操作菜单。
- 页面标题和添加链接按钮。
- 链接卡片、链接地址、分组标签和操作区。
- 添加及编辑链接弹窗。
- 删除链接和删除分组确认弹窗。
- 复制成功反馈。
- 搜索或分组无结果时的空状态。

### 3.3 明确不包含

- SQLite 持久化。
- Zustand 数据层重构。
- 链接和分组业务规则调整。
- 笔记、剪切板、设置模块的完整视觉迁移。
- 链接“打开”按钮业务行为补全。
- 全量删除旧 CSS。

## 4. 兼容策略

链接与笔记目前共用 Button、Dialog 和分组相关组件。为避免笔记模块回归：

1. 优先维持现有公共组件的 props 和可访问名称。
2. 通过适配或内部替换逐步接入新组件。
3. 仅删除已确认不再使用的链接模块样式。
4. 公共组件变化必须运行链接、分组和笔记测试。

## 5. 视觉原则

- 风格定位为紧凑、清晰、克制的 Windows 桌面效率工具。
- 不直接套用网页后台模板。
- 默认窗口 960 × 680px、最小窗口 720 × 520px 下均可使用。
- 控件使用满足操作需要的最小合理尺寸。
- 使用 Lucide 图标替换字符图标。
- 强化 hover、focus、active、danger 和复制成功反馈。
- 长标题、URL 和分组名称需要可靠截断。
- 不通过放大卡片或增加无意义留白制造视觉效果。

## 6. 风险控制

- 控制 Tailwind 基础样式与现有全局 CSS 的冲突。
- 控制 Portal、焦点锁定和弹窗 DOM 变化对测试的影响。
- 避免公共组件替换导致笔记模块视觉或交互回归。
- 新旧样式共存期间禁止依赖大量 `!important` 覆盖。
- shadcn/ui 组件只按实际需要加入，避免无关依赖和代码膨胀。

## 7. 验收标准

1. 链接模块完成统一、精致的 shadcn/ui 视觉改造。
2. 添加、编辑、删除、复制、搜索和分组筛选行为保持可用。
3. 新增空结果状态和明确的操作反馈。
4. 键盘焦点、Escape 关闭、ARIA 名称等可访问性行为正常。
5. 960 × 680px 与 720 × 520px 下无明显溢出或布局破坏。
6. `pnpm test` 全部通过。
7. `pnpm build` 通过。
8. 笔记模块不因公共 UI 改造产生功能回归。
